# Out-of-the-box defaults of popular emulators (GBA focus)

Method and versions. Defaults were read from source code, fetched on 2026-10-29. Unless a tag is named, the branch read was the default branch (master/main/dev). The latest releases on that date were: mGBA 0.10.5 (2025-03), VBA-M v2.2.3 (2025-10), RetroArch v1.22.2 (2025-11), SkyEmu v5 (2026-02) and NanoBoyAdvance v1.8.3 (2026-05). Release versions come from the GitHub releases API. For VBA-M the v2.2.3 tag was read, because master has diverged a lot from it (see below). A value that is a code default but may be overridden at first run (a wizard or a runtime probe) is flagged. "Unverified" means no source was found.

## Comparison table: GBA-specific emulators (emulator × setting)

### Takeaway
The GBA desktop emulators agree on a few things: nearest-neighbour output with a locked aspect ratio, no integer scaling, rewind off, Enter for Start, F-keys for load state with Shift+F-key for save, and fullscreen off at start. They disagree on everything to do with how the image should look (colour correction, ghosting), on the fast-forward key and mode, on whether to pause on focus loss, and on the starting window scale (2x or 3x).

### Inferences
- Consensus: nearest-neighbour filtering, a locked 3:2 aspect ratio, integer scaling off, rewind off (except SkyEmu, which always has it), Enter for Start, and the "F# load / Shift+F# save" convention (mGBA, VBA-M, NBA, and Dolphin below). The slot count varies: 4, 8, 9 or 10.
- Disagreement on picture: the newer accuracy-focused emulators (NanoBoyAdvance, SkyEmu, ares) turn on GBA colour correction and LCD ghosting by default. mGBA and the libretro GBA cores leave both off. VBA-M turns on colour correction but not ghosting. Making either a visible toggle in gbaa's menu is better supported by this evidence than any one default.
- Disagreement on fast forward: Tab-hold (mGBA, SkyEmu, DuckStation, Dolphin's speed-limit toggle) versus Space (VBA-M hold, NBA hold, RetroArch toggle). The cap is usually unlimited (mGBA, RetroArch, DuckStation); NBA defaults to 2x.
- Face-button mapping on pads is split. mGBA and SkyEmu map by label (Xbox A → GBA A); VBA-M maps by position (right → A, bottom → B). RetroArch's RetroPad convention is also positional (RetroPad B = bottom = GBA B). This is a real design choice for gbaa's default pad map.
- Mainstream desktop frontends need no pad combo for the menu. RetroArch reserves Start+Select only on handheld-like builds (Switch, Miyoo), which suits a Start+Select menu combo in gbaa on handhelds. Start+Select is also a soft-reset chord in many GBA games (A+B+Start+Select), so the combo should probably need a hold or be configurable. This is an inference; I found no source.

### Gaps
- SkyEmu: sample rate constant, sync mode, BIOS behaviour and pause-on-focus defaults were not located in main.c.
- VBA-M: speed-up throttle percentage, rewind interval default and speed-up mute default sit in core option structs outside the files read. SRAM default location is inferred from an empty `battery_dir`.
- mGBA: whether `fastForwardMute` and `fastForwardVolume` default to muted. The "Load last state" setting is on by default, but I did not trace exactly which state it loads.
- VBA-M master (unreleased) has diverged a lot. It has a runtime "filter probe" that picks a filter on first ROM load (placeholder default xBRZ 2x), vsync defaults on for macOS only, 3 audio buffers, HDR and colour-profile auto settings, and DLSS options — [VBAM-Master](https://github.com/visualboyadvance-m/visualboyadvance-m/blob/master/src/wx/config/internal/option-internal.cpp). The next release's defaults may differ from 2.2.3.

## Other emulators (OpenEmu, Delta, ares, melonDS, Snes9x, DuckStation, Dolphin)

### Takeaway
Among the general and other-system emulators, defaults on focus loss, resume state and smoothing are split. DuckStation and melonDS smooth (bilinear) by default; ares, Snes9x and Dolphin do not. DuckStation saves state on exit; Delta auto-saves states in the background. ares and Delta pause when the window loses focus; DuckStation, Dolphin and Snes9x do not. Dolphin uses the same F#/Shift+F# save-state convention as mGBA, VBA-M and NBA.

### Cited Findings
- **ares**:
  - Video: shader "None", output "Scale" at fixed scale 2, window 800×576, aspect correction "Standard", adaptive sizing on. `colorEmulation = true` and `interframeBlending = true`, which means GBA colour correction and ghosting are both on by default. Overscan on. Exclusive fullscreen off — [ares-Set](https://github.com/ares-emulator/ares/blob/master/desktop-ui/settings/settings.hpp)
  - Audio: frequency 0 and latency 0 (driver default), `blocking = true` (sync to audio), `dynamic = false`, volume 1.0 — [ares-Set](https://github.com/ares-emulator/ares/blob/master/desktop-ui/settings/settings.hpp)
  - Input: defocus = "Pause" — [ares-Set](https://github.com/ares-emulator/ares/blob/master/desktop-ui/settings/settings.hpp)
  - General: rewind off (length 80, frequency 60, not muted), run-ahead off, `autoSaveMemory = true`, fast boot off — [ares-Set](https://github.com/ares-emulator/ares/blob/master/desktop-ui/settings/settings.hpp)
  - Hotkeys exist for Fast Forward (hold) and Toggle Fast Forward, plus Rewind, Save/Load State with slot +/−, Pause, Fullscreen, Pseudo-Fullscreen and Mouse Capture. No default keys are assigned in hotkeys.cpp (inferred: unbound by default) — [ares-HK](https://github.com/ares-emulator/ares/blob/master/desktop-ui/input/hotkeys.cpp)
- **melonDS**:
  - `Screen.Filter = true` (bilinear smoothing on by default). VSync is not among the true defaults (so off), with interval 1. The window starts at 256×384 (1x, both screens) — [melon-Cfg](https://github.com/melonDS-emu/melonDS/blob/master/src/frontend/qt_sdl/Config.cpp)
  - Audio volume 256 (the maximum); `LimitFPS = true` at 60 fps; fast-forward target 1000 fps (effectively uncapped); slow-motion 30 fps — [melon-Cfg](https://github.com/melonDS-emu/melonDS/blob/master/src/frontend/qt_sdl/Config.cpp)

- **Snes9x (GTK)**: no fullscreen on open; scale to fit with aspect ratio maintained; bilinear off; sync to vblank on; `pause_emulation_on_switch = false`; rewind off (granularity 5, buffer 0); playback 48000 Hz with a 48 ms buffer (`sound_buffer_size = 48`); dynamic rate control off; sound sync off; `save_sram_after_secs = 0` and `AutoSaveDelay = 0`; turbo frame skip 15 — [S9x-GTK](https://github.com/snes9xgit/snes9x/blob/master/gtk/src/gtk_config.cpp)
- **DuckStation**:

  - Behaviour: `PauseOnFocusLoss = false`; `SaveStateOnExit = true` (resume state); `ConfirmPowerOff = true`; `RewindEnable = false`; `FastForwardSpeed = 0` (unlimited); volume 100 — [DS-Set](https://github.com/stenzek/duckstation/blob/master/src/core/settings.cpp)

### Inferences
- Convention clusters for save-state keys:
  1. Per-slot F# load / Shift+F# save: mGBA, VBA-M, NanoBoyAdvance, Dolphin.
  2. Current-slot save/load keys with a slot selector: RetroArch (F2/F4, F6/F7), DuckStation (F1/F2, F3/F4), ares (unbound).
  3. Number row to save, F-row to load: SkyEmu.

  gbaa's F10 menu key collides with mGBA's F10 "load current slot" and Dolphin's F10 play/pause. It does not collide with VBA-M or NBA if gbaa uses 9 slots or fewer on F1–F9.
- Fullscreen: Alt+Enter (mGBA on Windows/Linux, VBA-M, Dolphin) and F11 (SkyEmu, DuckStation) are the two common choices. Binding both is common practice; Esc to leave fullscreen appears in mGBA.
- Resume-where-you-left-off is the default in the more consumer-oriented frontends (DuckStation's save on exit, Delta's auto save, SkyEmu's 30 s autosave). It is off in the classic desktop GBA emulators (VBA-M, RetroArch, mGBA's periodic autosave).
- Pause on focus loss is split about evenly (on: RetroArch, NBA, ares, Delta; off: mGBA, VBA-M, DuckStation, Dolphin, Snes9x). Neither choice can claim to be "the standard".

### Gaps
- OpenEmu global hotkeys, video filter default, colour correction and save behaviour could not be sourced from the repo files reached. OpenEmu keeps per-core shader preferences elsewhere.
- Delta: the GBA core's colour correction, rewind availability and default, and auto-save interval were not found in the FAQ pages read.
- melonDS and Snes9x default key assignments were not located in the config files read.
- Gamepad auto-mapping in RetroArch (which autoconfig profile binds Guide to the menu, for example) was not verified; it lives in the separate retroarch-joypad-autoconfig repo.
